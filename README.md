# HodoCode.nvim

通常のNeovim編集バッファに、HodoCodeの関数一覧・呼び出しツリー・ローカル構文解説を追加します。Neovim 0.10以降とGo 1.23以降が必要です。ツリーはSnacks.nvimが利用できればそのpickerを使い、なければ標準フロートへフォールバックします。追加の必須プラグインはありません。

## セットアップ

このリポジトリでバックエンドをビルドし、Neovimのruntimepathに追加してください。

```sh
make build
```

```lua
-- 利用するプラグインマネージャーで読み込んだ後に設定する。
require('hodocode').setup({
  language = 'auto',
  -- root = '/path/to/project', -- 未指定時は近いgo.mod/.git等から検出
})
```

バックエンドは既定でこのプラグインの`bin/hodocode`です。別のビルドを使う場合は`backend = { '/absolute/path/to/hodocode' }`を指定します。コマンドはシェルを通さずargvとして起動します。

## 操作

迷ったらソース上で`:HodoCode`から操作を選択してください。従来の`<leader>h`で入る読解モードと個別コマンドも使えます。

- 読む：保存 → `<leader>h` → `n/N`で呼び出し名 → `Enter`で定義 → `b`で戻る。`s`は構文・関数・変数情報、`t`はツリー、`m`は図。
- 解説・会話：`a`はカーソル行（指示可）、`E`は現在の関数、`K`は注釈全文。`e/i`で同じエージェント会話を開き、`Enter`で質問します。
- 編集：`A`で依頼 → `Ctrl-s`で送信 → 未保存バッファの`🤖`を確認 → `d`でdiff → 必要なら`u`で戻すか`:write`で保存。`x`は中止です。

| コマンド | 動作 |
| --- | --- |
| `:HodoCode` | 分類・キー付きの操作一覧から選択（モード外でも利用可） |
| `:HodoCodeMode` | 操作元バッファでHodoCodeモードを開始 |
| `:HodoCodeModeExit` | モードを終了してキー割り当てを復元 |
| `:HodoCodeFunctions` | プロジェクトの関数一覧から移動 |
| `:HodoCodeCalls` | カーソル位置の関数を起点に呼び出しツリーを表示 |
| `:HodoCodeSyntax` | カーソル位置の構文をポップアップで解説 |
| `:HodoCodeReload` | バックエンドを再起動して再解析 |
| `:HodoCodeFollow` | カーソル上の確定したローカル呼び出し先へ移動 |
| `:HodoCodeGraph` | import依存／関数呼び出し図の共通画面（Tabで切替） |
| `:HodoCodeExplain [指示]` | カーソル位置の関数だけをマスクして解説アダプターへ送信し、行注釈を表示 |
| `:HodoCodeNote` | カーソル行の注釈全文と全体要約をポップアップ表示 |
| `:HodoCodeNotesToggle` / `:HodoCodeNotesClear` | 注釈表示の切替／消去 |
| `:HodoCodeChat` | 同じエージェント会話・実行状況を開く／再表示（`A`と共通の`agent`接続） |
| `:HodoCodeAgent [指示]` | 現在のバッファをAIで編集（未保存内容を含む全文を送信。自動保存しない） |
| `:HodoCodeCancel` | 実行中の依頼・行解説を中止。エージェント会話履歴は保持 |
| `:HodoCodeDiff` | ソース行直下のインラインdiffをオン・オフ。直近に適用された依頼の開始時保存済み内容が基準 |

内容表示フロートは`q`／`Esc`で閉じてソースへ戻り、通常のNeovim操作でスクロールできます。エージェント画面を閉じても会話と実行中の依頼は継続します。ソース上の`q`／`Esc`は従来どおりHodoCodeモード終了です。モードのガイドは枠なし1行で、操作一覧への入口・終了・保存状態・AI状態だけを表示します。詳細キーは`?`で確認できます。操作に迷った場合は`:HodoCode`で操作を選ぶか、モード中の`?`で全キーと操作の流れを確認できます。HodoCodeが開く内容表示用ポップアップ（構文・行解説・図・エージェント会話・標準／Snacks呼び出しツリー）は、タイトルを省いた単線枠で、原則として画面の約90%幅・80%高に中央表示し、画面リサイズにも追従します。Markdownは追加プラグインなしで見出し・太字・コード・リンクを強調し、一部の記号を隠して表示します（本文は変更しません）。内容が短くても縮めず、小画面では収まる大きさに制限します。モードのキーガイドと外部UIが管理する関数選択・指示入力は例外です。呼び出しツリーは`Space`／`Tab`で展開・折り畳み、`h/l`で閉じる／展開、`Enter`／`o`で定義へ移動します。展開状態・選択位置は確認できたソースが変わらない間、再表示時に保持します。循環は表示して展開を止め、未解決理由・候補は確定呼び出しと区別します。`tree = 'native'`で標準フロートを選べます（既定は`'auto'`）。定義・参照・変数強調などは既存のNeovim側LSPを使ってください。

解析対象は保存済みソースです。未保存変更中の解析操作は理由を表示して止めます。保存時には古い解析プロセスを破棄し、次の操作時に再解析します。各読解操作の前にもスナップショットを更新し、現在のバッファやファイルが応答待ち中に変わった場合は結果を表示しません。表示済みの構文・ツリーもソース変更時に閉じます。解析はバックエンド内で直列、Neovimとの通信は非同期です。長時間応答しないバックエンドはタイムアウトで停止します。

Go・Zig・TypeScript・Rust・C・JavaScript・Pythonの対応はコピーしたHodoCodeに従います。Goの`_test.go`は解析対象外です。非Go言語はHodoCode側が別プロセスの言語サーバーを起動します。対象プロジェクト・言語にNeovim側LSPが接続済みの場合は、二重起動を避けるため解析を止め、役割分担の確認を求めます。既存Neovim LSPの再利用や自動停止・再起動は未対応です。Go以外の必要ツールと制限は[`backend/docs/languages.md`](backend/docs/languages.md)を参照してください。未導入時のエラーを隠して字句解析へフォールバックすることはしません。信頼できるプロジェクト・言語サーバーだけで利用してください。

## HodoCodeモード

`<leader>h`でモードに入ります。`vim.g.mapleader = " "`ならSpace→hです。既に同じキーが設定されている場合、その設定を上書きしません。明示的に割り当てる場合、lazy.nvimのHodoCode設定には以下を追加します。以前の`<leader>hf`などの個別割り当てはこの1件へ置き換えてください。

```lua
keys = {
  { "<leader>h", "<cmd>HodoCodeMode<cr>", desc = "HodoCodeモード", nowait = true },
},
```

開始後はSpaceを押し直さず操作できます。画面下部にモード名とキーガイドを表示し、`h/j/k/l`は通常の移動のままです。保存済みの対応ソースでは、解析で識別できる関数名（宣言・呼び出し・関数参照）を下線でマークします。外部・未解決・曖昧な呼び出し名も対象です。そのうち`Enter`で移動できる確定したローカル呼び出し先は、黄色背景・太字・下線でさらに強調します。移動先に未保存変更がある場合は通常の下線に戻します。カーソルが乗っていなくても表示し、関数全体の背景は塗りません。編集後・モード終了時には消し、保存後は位置を再取得します。未保存・未対応のバッファではマーカーを表示しませんが、モード自体は利用できます。モードに入るだけでAIへ送信することはありません。

通常の関数名は`HodoCodeFunctionName`、ジャンプ可能な呼び出し名は`HodoCodeFunction`ハイライトで調整できます。既存の独自ハイライト設定は上書きしません。ソース本文や既存の選択範囲は変更しません。

基本の読解は **`n/N`で呼び出し名を選ぶ → 黄色の名前で`Enter` → `b`で戻る** です。画面下のガイドはよく使う操作だけに絞り、`?`で分類別の操作一覧を開けます。操作一覧は`q`／`Esc`／`?`で閉じてソースへ戻り、`Ctrl+C/D`ではモードも終了します。狭い画面ではガイドを簡略化し、操作一覧と終了キーを優先表示します。

| 分類 | キー | 操作 |
| --- | --- | --- |
| 移動 | `n` / `N` | 現在の関数内の次／前の呼び出し名へ移動（出現順、端で停止） |
| 移動 | `Enter` / `b` | 確定した呼び出し先へ進む／直前の読解位置へ戻る |
| 移動 | `g` / `G` | ファイルではなく現在の関数の先頭／末尾へ移動（`gg`も先頭） |
| 表示 | `t` / `f` | 呼び出しツリー／関数一覧 |
| 表示 | `s` | 構文・関数・変数情報。Goの変数では型・宣言・初期化式・参照／更新箇所を表示。停止中のDAPがあれば安全に取得できる実値も表示 |
| 表示 | `m` / `r` | 依存・呼び出し図／再解析 |
| 注釈 | `K` / `c` / `z` | カーソル行の注釈全文／注釈表示切替／注釈消去（AI送信なし） |
| 表示 | `[` / `]` | 開いている標準ポップアップを上／下へスクロール |
| AI | `E` | 現在の関数全体の行解説を生成 |
| AI | `a` | カーソル行だけを解説。指示を入力でき、空欄で確定すると通常の行解説 |
| AI | `e` / `i` | 同じエージェント会話・実行状況を開く／再表示 |
| AI | `A` | 現在のバッファをAIで編集（指示を入力。全文送信・未保存で反映） |
| AI | `x` / `d` | 実行中止（履歴保持）／行直下diffの表示切替 |
| ヘルプ | `?` | 分類別の操作一覧 |
| 終了 | `q` / `Esc` / `Ctrl+C` / `Ctrl+D` | HodoCodeモード終了（Neovim自体は終了しない） |
| 終了 | `v` | モードを終了して通常のNeovim編集へ戻る |

`s`の変数情報はGoが対象です。初期化式・定数値・宣言時のゼロ初期化を現在値とは区別します。任意依存の`nvim-dap`が既に停止中なら、同じファイル・関数範囲の選択フレームから、一意に対応するローカル変数・引数・名前付き戻り値だけを取得します。デバッグの自動開始・任意式の評価・AI送信はしません。詳しくは[変数情報](docs/variables.md)を参照してください。

`s`の関数情報は、Go標準ライブラリには事前収録した日本語カタログを使い、表示時にAIを呼びません。カタログはGo SDK `go1.27.4`の公開関数・公開型のメソッドを、全プラットフォームのソースから抽出したものです（`internal`・`vendor`・`cmd`・`testdata`・テストファイルは除外）。原文コメントのSHA-256が一致する訳文だけを表示し、SDK更新などで原文が変わった場合は原文表示へ戻します。コメントのない関数にはその旨を表示します。見出しは「構文・使用例・注意点・参照元」、シグネチャや識別子は原文のままです。

外部依存ライブラリの関数には、既存の`explain_agent`を使って表示時に日本語訳を生成します。送信するのは対象関数の名前・シグネチャ・定義コメントだけで、プロジェクトのソース本文や他ファイルは送らず、プロジェクトの絶対パスもメタデータとして付けません。訳文は同じポップアップへ反映し、成功した64件をNeovimセッション内でキャッシュします。ポップアップを閉じる・ソースを変更する・`:HodoCodeCancel`を実行すると処理を中止します。未設定・タイムアウト・不正応答では理由と原文を表示します。repo独自関数のコメントは自動送信せず、従来どおり表示します。

標準カタログの再生成手順・対象範囲・ライセンスは[`docs/stdlib-ja.md`](docs/stdlib-ja.md)を参照してください。

元のTUIのキーに合わせています。旧割り当てから`c`はツリー→行解説表示切替、`t`はチャット→ツリー、`g`は図→関数先頭、`v`は注釈表示切替→通常編集へ戻る、に変更しました。図は`m`、チャットは`e/i`です。`3n`などのcountにも対応し、移動ごとに再解析せず取得済みの呼び出し位置を利用します。TUIと同様、未解決・外部の呼び出し名も`n/N`で選べますが、`Enter`で確定先へ飛べるとは扱いません。解析待ち・未保存時は移動を止めます。

`a/E`は編集用の`A`／`HodoCodeAgent`ではなく、送信前処理付きの読み取り専用行解説です。`e/i`はHodoCode管理の会話画面で、`A`と同じセッション・接続先を使います。`Esc`・画面を閉じる・モード終了・別バッファへの移動では依頼を中止しません。元TUIの`v`は外部Neovim起動でしたが、既にNeovim内なのでモード終了に置き換えています。`h/j/k/l`・矢印・`w/B`・`0/$`・PageUp/Down・`/`検索はNeovim標準を使います（`?`は操作一覧、`n/N`は呼び出し名の移動です）。未実装の変数専用ポップアップ用`{}`は上書きしません。

操作元バッファで終了キーを押すか、挿入モードへ移るか、手動で別の通常バッファへ移動すると終了します。HodoCodeからの関数ジャンプと`b`による復帰では別ファイルでもモードを維持し、元のカーソル・スクロール位置を復元します。通常のNeovimジャンプ履歴も維持します。一時変更したバッファローカルのキーは終了時に復元します（モード中にユーザーが別の割り当てへ変更したキーは上書きしません）。フロート内にはソース用のモードキーを持ち込まず、各画面固有の操作を優先します。フロートを閉じて操作元へ戻るとモードを続けられます。`d`のインラインdiffはウィンドウを移動せず、読解モードを維持します。モードを終了しても会話と実行中の依頼は継続します。

which-keyを使っている場合、従来の`<leader>h`グループ設定も外すと、モードへの入口を1つの操作として表示できます。Snacks.nvimやwhich-keyへの依存はありません。

## 解析前のエラー案内

未対応の拡張子（Luaなど）、`language`設定と開いているファイルの言語の不一致、Goの`go.mod`不足、対象外の`_test.go`は、バックエンド起動前に理由と対処を表示します。Luaは`language = "auto"`にしても未対応です。Goは`go.mod`配下の通常の`.go`ファイルで実行してください。dotfilesなど対象外のディレクトリに、エラー回避のためだけに`go.mod`を追加する必要はありません。

## 図の試用

`m`／`:HodoCodeGraph`で開き、`Tab`でimport依存と現在の関数の呼び出し図を切り替えます。現段階の既定表示は**Mermaidソース**で、視覚的な図レンダラーは未選定です。呼び出し図は起点の一段分で、制御フロー図ではありません。APIでは明示した枝の追加展開にも対応します。

既存の図プラグインを試す場合は`graph_renderer = function(graph, view) ... end`を指定できます。`graph`は`kind/nodes/edges/mermaid`、`view`は表示用`buf/win/root`を持ちます。標準では外部コマンド・Webサービスを呼ばず、失敗時もソース表示を残します。設定したコールバックの通信・副作用は利用者側で確認してください。

## 行解説とエージェント会話の試用

接続先は未設定です。まずUIだけ試すなら、ネットワーク通信しないPython 3製デモを明示設定できます（**AIの回答ではありません**）。パスはこのリポジトリの導入先へ置き換えてください。

```lua
require('hodocode').setup({
  language = 'go',
  explain_agent = { 'python3', '/absolute/path/to/HodoCode.nvim/examples/explain-demo.py' },
  agent = { 'python3', '/absolute/path/to/HodoCode.nvim/examples/chat-demo.py' }, -- 会話・編集共通、変更なしのデモ
  excludes = { 'private', '*.secret.go' }, -- プロジェクト相対、ファイル・ディレクトリ・glob
})
```

名前付きの対応言語バッファで`E`または`:HodoCodeExplain`を実行すると、要求開始時のカーソルを含む関数だけ（宣言から末尾まで、未保存の編集も含む）を解説アダプターへ渡します。ローカルでバッファ全文の文字列・コメント空白化と除外・サイズ検査を行い、関数の行範囲だけ切り出すため、他の関数やファイル先頭のコードはAIへ送りません。関数外では通知して中止し、全文送信には切り替えません。`a`は開始時のカーソル行だけを切り出して解説します。指示入力を残し、空欄で確定した場合は通常の行解説、入力した場合はその指示に従った行解説です。入力を取り消した場合は送信しません。関数外の行でも利用できます。追加確認は出しません。解説は`virtual_text`、`K`でカーソル行の全文、`c`で表示切替、`z`で消去できます。編集・保存後は古い注釈を消し、版が合わない遅延応答は捨てます。解析APIと異なり、この前処理だけなら`go.mod`・言語サーバーは不要です。Luaなど未対応言語は送信しません。

`e/i`でHodoCodeの会話画面を開くと、折り返しの長い行も含めて最新の末尾を表示します。画面内の`Enter`／`i`で質問し、`?`で必要な時だけ操作説明を開けます。常設のタイトル・長い操作案内・送信済み等の重複表示は省いています。更新は差分だけを描画し、末尾を表示中なら追従、過去ログの閲覧中はスクロール位置を維持します。`A`は同じ会話への編集指示です。`Esc`／`q`／ウィンドウだけの`:q`は画面を隠すだけで、再度`e`を押すと履歴と実行状況を再表示します。`x`は依頼だけを中止し、履歴を残します。セッションが終了するのはNeovim本体の終了時です。

質問・編集の接続先は共通の`agent`です。旧`chat`のCLI端末・`{context}`引数は使用しません。各依頼で、その時点の対象ファイル・未保存本文・カーソルと、このNeovim内の会話履歴を渡します。**会話にも生の全文を送信するため、マスク済みの`a/E`とは送信範囲が異なります。** 外部CLIが直接ファイルを変更する方式には接続しないでください。

`explain_agent`による行解説は独立して従来の保護経路を使います。

- stdin：`{"prompt":"指示","buffer":{"file":"main.go","path":"main.go","content":"対象関数または行だけのマスク済み本文","version":"元全文のSHA-256","language":"go","start_line":1,"end_line":2}}`。`version`は元バッファ全文のSHA-256です。
- stdout：`{"version":"同じSHA-256","message":"全体要約","comments":[{"file":"main.go","line":1,"end_line":2,"text":"行解説全文"}]}`。相対行を元バッファへ戻し、ファイル・版・範囲が不正なら全体を拒否します。ソースは書き換えません。
- 前処理は入力JSON最大1MiB、ソース／準備済みJSON各128KiB、指示8KiBです。応答上限は`max_agent_bytes`、処理時間は`agent_timeout_ms`です。マスキングはヒューリスティックで、秘密の完全除去は保証しません。
- 専用一時ディレクトリをcwdにしますが、OSのサンドボックスではありません。アダプターが独自に読むファイルや子プロセスには送信保護を強制できません。別ファイルが残った場合は警告し、勝手に再帰削除しません。

## バッファのAI編集と保存済み内容とのdiff

HodoCodeモードの`A`または`:HodoCodeAgent`で、同じ会話への編集依頼ポップアップを開きます。複数行を入力でき、`Ctrl-s`／`Ctrl-Enter`またはノーマルモードの`Enter`で送信します。挿入モードの`Enter`は改行、`Esc`／ノーマルモードの`q`は未送信の入力だけを取り消します。`:HodoCodeAgent 指示`なら入力を省略でき、会話画面から実行してもその画面の対象ソースへ依頼します。`a/E`の解説用`explain_agent`は別設定・別保護経路のままです。`agent`が未設定なら送信せず設定案内を表示します。

fxを利用する場合は、macOS/LinuxでPython 3・設定済みの`fx`がPATHにある環境なら、同梱アダプターを明示設定できます（パスは導入先へ置き換えてください）。

```lua
require('hodocode').setup({
  agent = { 'python3', '/absolute/path/to/HodoCode.nvim/examples/edit-fx.py' },
  agent_timeout_ms = 120000,
  max_agent_bytes = 1024 * 1024,
})
```

アダプターは標準入力から次のJSONを1件読みます。質問・編集とも、送信時点の対象バッファ全文（未保存内容・文字列・コメントを含む）と、このセッションで送信済みの会話を渡します。勝手に他ファイルや外部CLIの履歴を読むことはなく、送信前の再確認も出しません。機密情報を含む本文・会話を送らないでください。入力（会話込み）、標準出力・標準エラー合計はそれぞれ`max_agent_bytes`以内で、超過時は履歴を勝手に切り捨てず送信を止めます。標準エラーの生データは画面へ転送しません。

```json
{"session_id":"同じNeovim内で共通のID","request_id":"依頼ごとのID","intent":"edit","history":[{"role":"user","content":"前の質問"},{"role":"assistant","content":"前の回答","status":"nochange"}],"prompt":"今の変更を踏まえて残りも直して","buffer":{"path":"/project/main.go","content":"package main\n","modified":true,"filetype":"go","cursor":[1,0]}}
```

新しい編集ブリッジは、1行1JSONの進捗と最後の結果を返します。`version`は要求の`buffer.content`のUTF-8バイト列のSHA-256です。

```jsonl
{"event":"status","phase":"waiting","elapsed_ms":1000}
{"event":"result","version":"要求元全文のSHA-256（64桁）","message":"変更の説明","edits":[{"old_text":"value = 1","new_text":"value = 2"}]}
```

部分編集は元のスナップショットに対する完全一致の置換です。最大256件、一意に一致し、範囲が重ならないものだけを全件まとめて検証・適用します。途中の進捗や一部の編集だけではバッファを書き換えません。`edits: []`は変更なしです。起動・応答待ち・受信・検証と経過時間を表示しますが、モデルの思考内容や生成完了率ではありません。失敗は`event: "error"`と分類コードで返し、画面には理由と経過時間を表示します。自動再送はしません。詳細は[編集ブリッジ仕様](docs/editing.md)を参照してください。

従来の単一JSON応答`{"message":"説明","content":"置換後の全文"}`も利用できます。会話共有には入力の`history`対応が必要で、同梱fxアダプターはこれをモデルへ渡します。質問の`intent: "chat"`では変更を受け付けず、`intent: "edit"`だけが適用対象です。実際の送信時点で対象バッファ・保存済みファイル・カーソル・設定を捕捉し、本文・名前・改行設定・ディスクが変わっていたら適用を止めます。フォーカス移動や元ウィンドウを閉じるだけでは失敗にせず、元のバッファへ反映します。`x`／`:HodoCodeCancel`は実行だけを中止し、遅延応答を適用しません。会話はNeovim内のメモリに保持し、本体終了時の`VimLeavePre`で処理と関連リソースを終了します。

書き換えが終わるとソースを更新し、会話へ結果を記録します。会話画面は勝手に閉じず、別のバッファを見ている場合もフォーカスを奪いません。`Esc`でソースへ戻れます。ディスクからの再読込・重い再解析・自動保存・diffの自動表示はしません。AIが変更・追加した行にvirtual textの`🤖 AI変更`を付け、削除だけの場合は近くの残った行に`🤖 AI削除`を付けます。要求前からの未保存編集をAI変更マーカーへ混ぜません。表示コストを抑えるためマーカーは最大1000行まで、手動編集・undo・保存・改名で消去します。

ソース上の`d`／`:HodoCodeDiff`はインラインdiffをオン・オフします。変更後の実際の行を強調し、対応する旧行を`-`付きで**その行のすぐ下**へ表示します。複数行置換も行ごとに対応付け、余った旧行は変更範囲の最後の行の下へ置きます。追加は実際の行を強調し、削除だけなら直前に残った行の下、先頭削除なら先頭行の上に表示します。`virt_lines`なので本文・行番号・undo履歴は変わらず、そのまま編集・`u`・`:w`が使えます。表示中の手動編集・undoでも差分を再計算します。

比較基準は、そのバッファへ直近に適用された依頼の開始時保存済み内容です。既存の未保存編集も差分に含み、保存後も基準を保持します。次の依頼が実際に変更を適用した場合だけ更新し、回答のみ・失敗・変更なしでは更新しません。その基準がなければ、diffをオンにした時点のディスク内容を固定して比較します。新規ファイルは空が基準です。行末改行・BOM・unix/dosだけの違いも仮想行で表示します。UTF-8（任意のBOM）と統一されたLF／CRLF改行に対応し、未対応エンコーディング・混在改行は拒否します。

アダプターは権限0700の一時ディレクトリで実行します。同梱fxアダプターは他ファイルの参照・ツール使用・ファイルへの直接書き込みを禁止する指示を渡し、プロバイダーへは絶対パスの代わりにファイル名を送ります。ただしプロセス自体はサンドボックスではありません。信頼できるアダプターのみを指定してください。直接ファイルを書き換えるCLIはこの経路に接続しないでください。

AI変更は自動でバッファに反映しますが、**勝手にディスクへ保存しません**。`u`で本文をAI変更前（既存の未保存編集を含む）へ戻せます。末尾改行オプションのundo補正は非同期で、利用者が明示的に変更した設定を優先します。元の改行コード・BOM設定は保持し、実際の保存はNeovimの`fixendofline`などの設定に従います。diffで確認し、保存する場合は通常の`:write`を使ってください。同梱fxアダプターは要求・応答各1MiBまでです。待機時間は`agent_timeout_ms`（既定120秒）から終了処理の余裕を差し引いた値に連動し、従来の固定115秒制限はありません。部分編集で返却トークンを減らせますが、モデル・入力サイズ・通信による待ち時間の短縮を保証するものではありません。ディスク上の外部変更は`FocusGained`・`BufEnter`時に未編集バッファだけ自動リロードし、未保存編集は上書きしません。常時ファイル監視は行いません。自動保存・複数ファイル編集・直接ファイルを編集するエージェントとの接続方式は、必要時に別途確認します。

## 開発

```sh
make test
```

Goのバックエンドテストと、headless Neovimによる実API通信・移動・構文・ツリー・図・行注釈・会話セッション・AI編集・行直下diff・undo・競合・リロード・Neovim終了時の実プロセス後始末のテストを実行します。AIテストはローカルのPython 3製テストアダプターを使い、実プロバイダーへ通信しません。Snacksの実表示も検証する場合は`HODOCODE_SNACKS=/absolute/path/to/snacks.nvim make test`を使います。未指定時は標準表示をテストし、Snacks専用の結合テストはスキップします。

バックエンドのコピー元は[`backend/UPSTREAM.md`](backend/UPSTREAM.md)、機械向けAPIは[`docs/api.md`](docs/api.md)、方針と未決事項は[`DESIGN.md`](DESIGN.md)を参照してください。
