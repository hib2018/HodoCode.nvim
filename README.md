# HodoCode.nvim

通常のNeovim編集バッファに、HodoCodeの関数一覧・呼び出しツリー・ローカル構文解説を追加します。Neovim 0.10以降とGo 1.23以降が必要です。ツリーはSnacks.nvimが利用できればそのpickerを使い、なければ標準フロートへフォールバックします。追加の必須プラグインはありません。

## セットアップ

このリポジトリでバックエンドをビルドし、Neovimのruntimepathに追加してください。

```sh
make build
```

```lua
-- 利用するプラグインマネージャーで読み込んだ後に設定する。
require('hodocode').setup({
  language = 'auto',
  -- root = '/path/to/project', -- 未指定時は近いgo.mod/.git等から検出
})
```

バックエンドは既定でこのプラグインの`bin/hodocode`です。別のビルドを使う場合は`backend = { '/absolute/path/to/hodocode' }`を指定します。コマンドはシェルを通さずargvとして起動します。

## 操作

| コマンド | 動作 |
| --- | --- |
| `:HodoCodeMode` | 操作元バッファでHodoCodeモードを開始 |
| `:HodoCodeModeExit` | モードを終了してキー割り当てを復元 |
| `:HodoCodeFunctions` | プロジェクトの関数一覧から移動 |
| `:HodoCodeCalls` | カーソル位置の関数を起点に呼び出しツリーを表示 |
| `:HodoCodeSyntax` | カーソル位置の構文をポップアップで解説 |
| `:HodoCodeReload` | バックエンドを再起動して再解析 |
| `:HodoCodeFollow` | カーソル上の確定したローカル呼び出し先へ移動 |
| `:HodoCodeGraph` | import依存／関数呼び出し図の共通画面（Tabで切替） |
| `:HodoCodeExplain [指示]` | カーソル位置の関数だけをマスクして解説アダプターへ送信し、行注釈を表示 |
| `:HodoCodeNote` | カーソル行の注釈全文と全体要約をポップアップ表示 |
| `:HodoCodeNotesToggle` / `:HodoCodeNotesClear` | 注釈表示の切替／消去 |
| `:HodoCodeChat` | マスク済みスナップショットをCLIチャットのターミナルフロートへ渡す |
| `:HodoCodeAgent [指示]` | 従来の編集用アダプター（生バッファ送信・下記注意） |
| `:HodoCodeCancel` | 行解説・チャット・従来のAI要求を中止 |
| `:HodoCodeDiff` | 現在のバッファと直近のAI変更前の版を別タブで比較 |

フロートは`q`で閉じ、通常のNeovim操作でスクロールできます。HodoCodeが開く内容表示用ポップアップ（構文・行解説・図・従来のAI出力・CLIチャット・標準／Snacks呼び出しツリー）は、原則として画面の約90%幅・80%高で中央表示し、画面リサイズにも追従します。内容が短くても縮めず、小画面では収まる大きさに制限します。モードのキーガイドと外部UIが管理する関数選択・指示入力は例外です。呼び出しツリーは`Space`／`Tab`で展開・折り畳み、`h/l`で閉じる／展開、`Enter`／`o`で定義へ移動します。展開状態・選択位置は確認できたソースが変わらない間、再表示時に保持します。循環は表示して展開を止め、未解決理由・候補は確定呼び出しと区別します。`tree = 'native'`で標準フロートを選べます（既定は`'auto'`）。定義・参照・変数強調などは既存のNeovim側LSPを使ってください。

解析対象は保存済みソースです。未保存変更中の解析操作は理由を表示して止めます。保存時には古い解析プロセスを破棄し、次の操作時に再解析します。各読解操作の前にもスナップショットを更新し、現在のバッファやファイルが応答待ち中に変わった場合は結果を表示しません。表示済みの構文・ツリーもソース変更時に閉じます。解析はバックエンド内で直列、Neovimとの通信は非同期です。長時間応答しないバックエンドはタイムアウトで停止します。

Go・Zig・TypeScript・Rust・C・JavaScript・Pythonの対応はコピーしたHodoCodeに従います。Goの`_test.go`は解析対象外です。非Go言語はHodoCode側が別プロセスの言語サーバーを起動します。対象プロジェクト・言語にNeovim側LSPが接続済みの場合は、二重起動を避けるため解析を止め、役割分担の確認を求めます。既存Neovim LSPの再利用や自動停止・再起動は未対応です。Go以外の必要ツールと制限は[`backend/docs/languages.md`](backend/docs/languages.md)を参照してください。未導入時のエラーを隠して字句解析へフォールバックすることはしません。信頼できるプロジェクト・言語サーバーだけで利用してください。

## HodoCodeモード

`<leader>h`でモードに入ります。`vim.g.mapleader = " "`ならSpace→hです。既に同じキーが設定されている場合、その設定を上書きしません。明示的に割り当てる場合、lazy.nvimのHodoCode設定には以下を追加します。以前の`<leader>hf`などの個別割り当てはこの1件へ置き換えてください。

```lua
keys = {
  { "<leader>h", "<cmd>HodoCodeMode<cr>", desc = "HodoCodeモード", nowait = true },
},
```

開始後はSpaceを押し直さず操作できます。画面下部にモード名とキーガイドを表示し、`h/j/k/l`は通常の移動のままです。保存済みの対応ソースでは、解析で識別できる関数名（宣言・呼び出し・関数参照）を下線でマークします。外部・未解決・曖昧な呼び出し名も対象です。そのうち`Enter`で移動できる確定したローカル呼び出し先は、黄色背景・太字・下線でさらに強調します。移動先に未保存変更がある場合は通常の下線に戻します。カーソルが乗っていなくても表示し、関数全体の背景は塗りません。編集後・モード終了時には消し、保存後は位置を再取得します。未保存・未対応のバッファではマーカーを表示しませんが、モード自体は利用できます。モードに入るだけでAIへ送信することはありません。

通常の関数名は`HodoCodeFunctionName`、ジャンプ可能な呼び出し名は`HodoCodeFunction`ハイライトで調整できます。既存の独自ハイライト設定は上書きしません。ソース本文や既存の選択範囲は変更しません。

基本の読解は **`n/N`で呼び出し名を選ぶ → 黄色の名前で`Enter` → `b`で戻る** です。画面下のガイドはよく使う操作だけに絞り、`?`で分類別の操作一覧を開けます。操作一覧は`q`／`Esc`／`?`で閉じてソースへ戻り、`Ctrl+C/D`ではモードも終了します。狭い画面ではガイドを簡略化し、操作一覧と終了キーを優先表示します。

| 分類 | キー | 操作 |
| --- | --- | --- |
| 移動 | `n` / `N` | 現在の関数内の次／前の呼び出し名へ移動（出現順、端で停止） |
| 移動 | `Enter` / `b` | 確定した呼び出し先へ進む／直前の読解位置へ戻る |
| 移動 | `g` / `G` | ファイルではなく現在の関数の先頭／末尾へ移動（`gg`も先頭） |
| 表示 | `t` / `f` | 呼び出しツリー／関数一覧 |
| 表示 | `s` / `m` / `r` | 構文解説／依存・呼び出し図／再解析 |
| 注釈 | `K` / `c` / `z` | カーソル行の注釈全文／注釈表示切替／注釈消去（AI送信なし） |
| 表示 | `[` / `]` | 開いている標準ポップアップを上／下へスクロール |
| AI | `E` | 現在の関数全体の行解説を生成 |
| AI | `a` | カーソル行だけを解説。指示を入力でき、空欄で確定すると通常の行解説 |
| AI | `e` / `i` | CLIチャットを開く（同じ操作の別名） |
| AI | `x` / `d` | AI処理中止／従来のAI編集前との差分 |
| ヘルプ | `?` | 分類別の操作一覧 |
| 終了 | `q` / `Esc` / `Ctrl+C` / `Ctrl+D` | HodoCodeモード終了（Neovim自体は終了しない） |
| 終了 | `v` | モードを終了して通常のNeovim編集へ戻る |

元のTUIのキーに合わせています。旧割り当てから`c`はツリー→行解説表示切替、`t`はチャット→ツリー、`g`は図→関数先頭、`v`は注釈表示切替→通常編集へ戻る、に変更しました。図は`m`、チャットは`e/i`です。`3n`などのcountにも対応し、移動ごとに再解析せず取得済みの呼び出し位置を利用します。TUIと同様、未解決・外部の呼び出し名も`n/N`で選べますが、`Enter`で確定先へ飛べるとは扱いません。解析待ち・未保存時は移動を止めます。

`a/E`は従来の編集用`HodoCodeAgent`ではなく、送信前処理付きの読み取り専用行解説です。`e/i`は設定したCLIの端末UIを開く操作で、TUIの会話・追加指示プロトコルそのものを移植したものではありません。元TUIの`v`は外部Neovim起動でしたが、既にNeovim内なのでモード終了に置き換えています。`h/j/k/l`・矢印・`w/B`・`0/$`・PageUp/Down・`/`検索はNeovim標準を使います（`?`は操作一覧、`n/N`は呼び出し名の移動です）。未実装の変数専用ポップアップ用`{}`は上書きしません。

操作元バッファで終了キーを押すか、挿入モードへ移るか、手動で別の通常バッファへ移動すると終了します。HodoCodeからの関数ジャンプと`b`による復帰では別ファイルでもモードを維持し、元のカーソル・スクロール位置を復元します。通常のNeovimジャンプ履歴も維持します。一時変更したバッファローカルのキーは終了時に復元します（モード中にユーザーが別の割り当てへ変更したキーは上書きしません）。フロート内にはソース用のモードキーを持ち込まず、各画面固有の操作を優先します。フロートを閉じて操作元へ戻るとモードを続けられます。別タブでdiffを開く場合は通常バッファの移動としてモードを終了します。

which-keyを使っている場合、従来の`<leader>h`グループ設定も外すと、モードへの入口を1つの操作として表示できます。Snacks.nvimやwhich-keyへの依存はありません。

## 解析前のエラー案内

未対応の拡張子（Luaなど）、`language`設定と開いているファイルの言語の不一致、Goの`go.mod`不足、対象外の`_test.go`は、バックエンド起動前に理由と対処を表示します。Luaは`language = "auto"`にしても未対応です。Goは`go.mod`配下の通常の`.go`ファイルで実行してください。dotfilesなど対象外のディレクトリに、エラー回避のためだけに`go.mod`を追加する必要はありません。

## 図の試用

`m`／`:HodoCodeGraph`で開き、`Tab`でimport依存と現在の関数の呼び出し図を切り替えます。現段階の既定表示は**Mermaidソース**で、視覚的な図レンダラーは未選定です。呼び出し図は起点の一段分で、制御フロー図ではありません。APIでは明示した枝の追加展開にも対応します。

既存の図プラグインを試す場合は`graph_renderer = function(graph, view) ... end`を指定できます。`graph`は`kind/nodes/edges/mermaid`、`view`は表示用`buf/win/root`を持ちます。標準では外部コマンド・Webサービスを呼ばず、失敗時もソース表示を残します。設定したコールバックの通信・副作用は利用者側で確認してください。

## 行解説とCLIチャットの試用

接続先は未設定です。まずUIだけ試すなら、ネットワーク通信しないPython 3製デモを明示設定できます（**AIの回答ではありません**）。パスはこのリポジトリの導入先へ置き換えてください。

```lua
require('hodocode').setup({
  language = 'go',
  explain_agent = { 'python3', '/absolute/path/to/HodoCode.nvim/examples/explain-demo.py' },
  chat = { 'python3', '/absolute/path/to/HodoCode.nvim/examples/chat-demo.py', '{context}' },
  excludes = { 'private', '*.secret.go' }, -- プロジェクト相対、ファイル・ディレクトリ・glob
})
```

名前付きの対応言語バッファで`E`または`:HodoCodeExplain`を実行すると、要求開始時のカーソルを含む関数だけ（宣言から末尾まで、未保存の編集も含む）を解説アダプターへ渡します。ローカルでバッファ全文の文字列・コメント空白化と除外・サイズ検査を行い、関数の行範囲だけ切り出すため、他の関数やファイル先頭のコードはAIへ送りません。関数外では通知して中止し、全文送信には切り替えません。`a`は開始時のカーソル行だけを切り出して解説します。指示入力を残し、空欄で確定した場合は通常の行解説、入力した場合はその指示に従った行解説です。入力を取り消した場合は送信しません。関数外の行でも利用できます。追加確認は出しません。解説は`virtual_text`、`K`でカーソル行の全文、`c`で表示切替、`z`で消去できます。編集・保存後は古い注釈を消し、版が合わない遅延応答は捨てます。解析APIと異なり、この前処理だけなら`go.mod`・言語サーバーは不要です。Luaなど未対応言語は送信しません。

`Space→h→e`（または`i`）でCLI本来のターミナルUIを開きます。入力後は`Ctrl-\\ Ctrl-n`でノーマルモードに戻り、`q`でセッションを終了できます。デモは`/quit`でも終了します。チャットは送信時点の固定スナップショットで、以後の編集を自動追送しません。

実接続では、下記のJSON仕様を話す信頼できるアダプターを指定してください。チャットの`{context}`は独立したargv引数が必要で、準備済みJSONファイルのパスへ置換します。アダプターはそのファイルを読み、対象CLIに安全に引き渡します。単に任意のCLIへこの引数を渡すだけでは連携しません。

- チャットのコンテキストJSON（全文）：`{"prompt":"指示","buffer":{"file":"main.go","path":"main.go","content":"マスク済み全文","version":"元全文のSHA-256","language":"go"}}`
- 行解説のstdinも同じ構造ですが、`buffer.content`は対象関数（`E`）またはカーソルの1行（`a`）だけ、`buffer.start_line`と`buffer.end_line`は元バッファの行範囲です。`version`は編集競合を検出するため元バッファ全文のSHA-256のままです。
- 行解説のstdout：`{"version":"同じSHA-256","message":"全体要約","comments":[{"file":"main.go","line":1,"end_line":2,"text":"行解説全文"}]}`。行は送信された範囲の先頭を1とする相対行番号（`a`では1のみ）、`end_line`は省略可能。Neovim側で元バッファの行番号へ戻します。ファイル・版・関数内の範囲が不正なら全体を拒否します。ソースの書き換えはしません。
- 前処理は入力JSON最大1MiB、ソース／準備済みJSON各128KiB、指示8KiBです。解説応答の上限は`max_agent_bytes`、処理時間は`agent_timeout_ms`です。マスキングは既存のヒューリスティックで、秘密の完全除去を保証しません。識別子・パス・指示も送信されます。
- チャットのコンテキストは権限`0700`の一時ディレクトリ内の`0600`ファイル。行解説・チャットとも一時ディレクトリをcwdにしますが、**サンドボックスではありません**。CLIが独自に読むファイル・履歴や子プロセスには、この送信保護を強制できません。終了・中止時は準備したファイルを削除しますが、アダプターが別ファイルを作った場合は残存パスを警告し、勝手に再帰削除しません。
- 試用チャットは読み取り専用の指示を渡しますが、権限制限ではありません。直接編集するCLIはまだ接続しないでください。直接編集・複数ファイル変更のdiff保証はありません。既存の自動リロードは未編集バッファだけで、未保存編集は上書きしません。

## 従来の編集用AIアダプター（生バッファ送信）

特定のプロバイダーや既存AIプラグインはまだ選択していません。AIアダプターを明示設定しない限り、外部へのコード送信はありません。コピー元の`explain --send`を編集エージェントと同一扱いにはしていません。

```lua
require('hodocode').setup({
  agent = { '/absolute/path/to/your-adapter', '--optional-argument' },
  agent_timeout_ms = 120000,
  max_agent_bytes = 1024 * 1024,
})
```

アダプターは標準入力から次のJSONを1件読み、標準出力へJSONを1件だけ返すプログラムです。ログは標準エラーへ出してください。現在のバッファ全文を未保存内容も含めて、送信直前の確認なしで渡します。他ファイル・会話履歴の自動添付はしません。文字列・コメントの空白化は行わないため、機密情報を含むバッファを送らないでください。送信量と出力量はそれぞれ`max_agent_bytes`以内です。

```json
{"prompt":"変更指示","buffer":{"path":"/project/main.go","content":"package main\n","modified":true,"filetype":"go","cursor":[1,0]}}
```

```json
{"message":"回答・変更の説明","content":"置換後のバッファ全文\n"}
```

`content`を省略すると回答のみです。現在のバッファ以外への編集はこのプロトコルでは対応しません。変更前の版はGitのHEADではなく、要求開始時点のバッファ（既存の未保存編集を含む）です。応答中にユーザーが編集した場合、改行設定を変えた場合、またはディスク上のファイルが変更された場合は競合として適用を止めます。アダプターは信頼できるものを指定してください。プロセス自体はサンドボックスではなく、直接ファイルを変更しないアダプターを想定しています。

AI変更は自動でバッファに反映しますが、**勝手にディスクへ保存しません**。保存は通常の`:write`で行います。ディスク上の外部変更は`FocusGained`・`BufEnter`時に未編集バッファだけ自動リロードし、未保存編集は上書きしません。常時ファイル監視は行いません。自動保存・複数ファイル編集・直接ファイルを編集するエージェントとの接続方式は、必要時に別途確認します。

## 開発

```sh
make test
```

Goのバックエンドテストと、headless Neovimによる実API通信・移動・構文・ツリー・図・行注釈・ターミナル・従来のAI変更・diff・競合・リロードのテストを実行します。AIテストはローカルのPython 3製テストアダプターを使い、実プロバイダーへ通信しません。Snacksの実表示も検証する場合は`HODOCODE_SNACKS=/absolute/path/to/snacks.nvim make test`を使います。未指定時は標準表示をテストし、Snacks専用の結合テストはスキップします。

バックエンドのコピー元は[`backend/UPSTREAM.md`](backend/UPSTREAM.md)、機械向けAPIは[`docs/api.md`](docs/api.md)、方針と未決事項は[`DESIGN.md`](DESIGN.md)を参照してください。
