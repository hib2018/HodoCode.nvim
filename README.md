# HodoCode.nvim

通常のNeovim編集バッファに、HodoCodeの関数一覧・呼び出しツリー・ローカル構文解説を追加します。TUIを埋め込む方式ではなく、Neovim標準のフロートを使います。Neovim 0.10以降とGo 1.23以降が必要です。Snacks.nvimは不要です。

## セットアップ

このリポジトリでバックエンドをビルドし、Neovimのruntimepathに追加してください。

```sh
make build
```

```lua
-- 利用するプラグインマネージャーで読み込んだ後に設定する。
require('hodocode').setup({
  language = 'auto',
  -- root = '/path/to/project', -- 未指定時は近いgo.mod/.git等から検出
})
```

バックエンドは既定でこのプラグインの`bin/hodocode`です。別のビルドを使う場合は`backend = { '/absolute/path/to/hodocode' }`を指定します。コマンドはシェルを通さずargvとして起動します。

## 操作

| コマンド | 動作 |
| --- | --- |
| `:HodoCodeFunctions` | プロジェクトの関数一覧から移動 |
| `:HodoCodeCalls` | カーソル位置の関数を起点に呼び出しツリーを表示 |
| `:HodoCodeSyntax` | カーソル位置の構文をポップアップで解説 |
| `:HodoCodeReload` | バックエンドを再起動して再解析 |
| `:HodoCodeAgent [指示]` | 設定済みAIアダプターへ現在のバッファを送信 |
| `:HodoCodeCancel` | 実行中のAI要求を中止 |
| `:HodoCodeDiff` | 現在のバッファと直近のAI変更前の版を別タブで比較 |

フロートは`q`で閉じ、通常のNeovim操作でスクロールできます。呼び出しツリーでは`Enter`で一段展開し、展開済みの項目では定義へ移動します。`o`は直接移動です。循環は表示して展開を止め、未解決理由・候補は確定呼び出しと区別します。定義・参照・変数強調などは既存のNeovim側LSPを使ってください。

解析対象は保存済みソースです。未保存変更中の解析操作は理由を表示して止めます。保存時には古い解析プロセスを破棄し、次の操作時に再解析します。各読解操作の前にもスナップショットを更新し、現在のバッファやファイルが応答待ち中に変わった場合は結果を表示しません。表示済みの構文・ツリーもソース変更時に閉じます。解析はバックエンド内で直列、Neovimとの通信は非同期です。長時間応答しないバックエンドはタイムアウトで停止します。

Go・Zig・TypeScript・Rust・C・JavaScript・Pythonの対応はコピーしたHodoCodeに従います。Goの`_test.go`は解析対象外です。非Go言語はHodoCode側が別プロセスの言語サーバーを起動します。対象プロジェクト・言語にNeovim側LSPが接続済みの場合は、二重起動を避けるため解析を止め、役割分担の確認を求めます。既存Neovim LSPの再利用や自動停止・再起動は未対応です。Go以外の必要ツールと制限は[`backend/docs/languages.md`](backend/docs/languages.md)を参照してください。未導入時のエラーを隠して字句解析へフォールバックすることはしません。信頼できるプロジェクト・言語サーバーだけで利用してください。

## 解析前のエラー案内

未対応の拡張子（Luaなど）、`language`設定と開いているファイルの言語の不一致、Goの`go.mod`不足、対象外の`_test.go`は、バックエンド起動前に理由と対処を表示します。Luaは`language = "auto"`にしても未対応です。Goは`go.mod`配下の通常の`.go`ファイルで実行してください。dotfilesなど対象外のディレクトリに、エラー回避のためだけに`go.mod`を追加する必要はありません。

## AI接続（任意・接続先は未設定）

特定のプロバイダーや既存AIプラグインはまだ選択していません。AIアダプターを明示設定しない限り、外部へのコード送信はありません。コピー元の`explain --send`を編集エージェントと同一扱いにはしていません。

```lua
require('hodocode').setup({
  agent = { '/absolute/path/to/your-adapter', '--optional-argument' },
  agent_timeout_ms = 120000,
  max_agent_bytes = 1024 * 1024,
})
```

アダプターは標準入力から次のJSONを1件読み、標準出力へJSONを1件だけ返すプログラムです。ログは標準エラーへ出してください。現在のバッファ全文を未保存内容も含めて、送信直前の確認なしで渡します。他ファイル・会話履歴の自動添付はしません。文字列・コメントの空白化は行わないため、機密情報を含むバッファを送らないでください。送信量と出力量はそれぞれ`max_agent_bytes`以内です。

```json
{"prompt":"変更指示","buffer":{"path":"/project/main.go","content":"package main\n","modified":true,"filetype":"go","cursor":[1,0]}}
```

```json
{"message":"回答・変更の説明","content":"置換後のバッファ全文\n"}
```

`content`を省略すると回答のみです。現在のバッファ以外への編集はこのプロトコルでは対応しません。変更前の版はGitのHEADではなく、要求開始時点のバッファ（既存の未保存編集を含む）です。応答中にユーザーが編集した場合、改行設定を変えた場合、またはディスク上のファイルが変更された場合は競合として適用を止めます。アダプターは信頼できるものを指定してください。プロセス自体はサンドボックスではなく、直接ファイルを変更しないアダプターを想定しています。

AI変更は自動でバッファに反映しますが、**勝手にディスクへ保存しません**。保存は通常の`:write`で行います。ディスク上の外部変更は`FocusGained`・`BufEnter`時に未編集バッファだけ自動リロードし、未保存編集は上書きしません。常時ファイル監視は行いません。自動保存・複数ファイル編集・直接ファイルを編集するエージェントとの接続方式は、必要時に別途確認します。

## 開発

```sh
make test
```

Goのバックエンドテストと、headless Neovimによる実API通信・移動・構文・ツリー・AI変更・diff・競合・リロードのテストを実行します。AIテストはローカルのPython 3製テストアダプターを使い、実プロバイダーへ通信しません。

バックエンドのコピー元は[`backend/UPSTREAM.md`](backend/UPSTREAM.md)、機械向けAPIは[`docs/api.md`](docs/api.md)、方針と未決事項は[`DESIGN.md`](DESIGN.md)を参照してください。
