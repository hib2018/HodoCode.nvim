# s の変数情報（Go）

Goの保存済みソースで変数名にカーソルを合わせ、HodoCodeモードの`s`を押します。関数名では従来の関数情報、キーワード・演算子では構文解説を表示します。変数表示にはAIを使用しません。

## 静的に表示する情報

- 型、種類（ローカル変数・引数・名前付き戻り値・フィールド・パッケージ変数・定数）、宣言元。
- 宣言時の初期化式、定数として確定できる値、明示的なゼロ初期化。型に応じたゼロ値は、数値なら0、boolならfalse、文字列なら空文字列、スライス・ポインタなどならnil、構造体・配列なら各要素のゼロ値です。
- 現在の関数内の参照箇所（代入先を含む）と、直接の代入・更新箇所。閉包内の参照も含み、同名でも別の宣言の変数は混ぜません。

フィールドの参照・更新一覧は同じフィールド宣言を基準にするため、異なるインスタンスを含みます。同じ実行時ストレージや値であることは保証しません。

これらは現在値の追跡ではありません。例えば`n := 1; n++`では、初期値の1と更新式の`n++`を表示しても、カーソル行の値を2とは断定しません。分岐・ループ・呼び出し結果は実行しません。ポインタ・スライスなどを介した変更や、呼び出し先・別ゴルーチンでの変更は網羅しません。

引数・フィールド・外部の初期化など、ゼロ初期化を確認できないものを勝手にゼロ値とは扱いません。未保存のバッファは実行前に拒否し、解析中・表示中の編集やディスク変更では古い応答・表示を破棄します。

## 停止中の実値：任意の nvim-dap 連携

`nvim-dap`の導入・アダプター設定・デバッグ開始・停止は利用者が行います。HodoCodeは自動インストールもデバッグ開始もしません。未導入・未接続・実行中なら、理由と静的情報だけを表示します。

実値を取得するのは次の条件を満たす場合です。

- 選択中フレームが停止中で、そのソースが同じファイル・解析した関数の範囲内にある。
- 対象がローカル変数・引数・名前付き戻り値で、関数内に同名の別の束縛がなく、デバッガーのローカル／引数スコープでも名前が一意に一致する。
- 取得中のセッション・スレッド・フレーム・ソースが変化していない。

フィールド・パッケージ変数・定数や、同名変数が複数ある場合は実値取得を見送ります。DAPの`scopes`と`variables`だけを読み、`evaluate`・関数呼び出し・子要素の展開は行いません。取得は3秒でタイムアウトします。

値には選択フレームのファイル・行・フレーム名・IDを併記します。停止行と編集カーソル行が違う場合は「カーソル行の値ではありません」と表示します。デバッグバイナリと保存済みソースの一致そのものは検証できないため、その注意も常に表示します。

ポップアップを閉じる・`:HodoCodeCancel`・ソース編集で処理を取り消します。実行再開・フレーム変更では取得済みの値も無効化します。遅延応答でポップアップを開き直したり、フォーカスを奪ったりしません。変数情報や実値を外部AIに送信することはありません。
