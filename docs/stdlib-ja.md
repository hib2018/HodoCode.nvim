# 構文解説の日本語データ

## 標準ライブラリ：事前収録

Go SDK `go1.27.4` のソースから、公開関数と公開型のメソッドの定義コメントを抽出します。全プラットフォームのソースを対象とし、`internal`、`vendor`、`cmd`、`testdata`、隠しディレクトリ、`*_test.go` は除外します。型・定数・パッケージ自体のコメントや、コメントのない宣言はこの関数カタログには含めません。

重複する原文をまとめた対象は **5,717件**です。訳文は `backend/internal/analyze/stdlib_ja.json` に収録し、Goバックエンドへ埋め込みます。表示時にはAIを呼びません。SDKメソッドも同じカタログを使います。

キーは `ast.FuncDecl.Doc.Text()` の原文のSHA-256です。末尾の改行を含む原文が一致する場合だけ訳文を使います。SDKの版やプラットフォームが異なっても原文が同じなら再利用できます。原文が変わった関数は誤った訳を当てず、既存40件の定型説明または未登録表示と原文へ戻します。コメントのない関数はその旨を表示します。

事前生成にはfxを使用します。今回の収録はCLIでの一括生成とfx子エージェントによる分担生成を併用し、同じ検査を通した訳文だけを取り込んでいます。全件のID一致・日本語文字・空文字・NUL・明らかな短縮・アスタリスクとバッククォートの個数を機械検証しますが、全件を人手で校閲済みという意味ではありません。API名・コード・リンクは翻訳しないよう指定しています。訳文の正確性が重要な判断には、参照元の原文も確認してください。

fxのJSON応答は加工前の`output`を読みます。`final_output`はプレーンテキスト化でポインタ記号やバッククォートが失われる版があるため、構造化JSONの取得には使わないでください。コード中を含むアスタリスク（ポインタ記号）とバッククォートは、翻訳中はプレースホルダーで保護し、復元後に原文と個数が一致することを検証します。

原文の著作権・ライセンスは [`stdlib_ja.LICENSE`](../backend/internal/analyze/stdlib_ja.LICENSE) を参照してください。

### 再生成

```sh
go run tools/stdlib-docs/main.go > /tmp/hodocode-stdlib-docs.json
python3 tools/translate_stdlib.py /tmp/hodocode-stdlib-docs.json backend/internal/analyze/stdlib_ja.json --workers 4
python3 tools/translate_stdlib.py /tmp/hodocode-stdlib-docs.json backend/internal/analyze/stdlib_ja.json --check
make build
```

抽出・`--check`・ビルドはAIを呼びません。翻訳コマンドだけがfxを呼びます。大量のリクエストとなるため、利用料金とモデルの利用制限を確認してください。成功したバッチは原子的に保存し、同じコマンドの再実行では未収録分だけを処理します。各バッチは300秒でタイムアウトします。失敗すると未開始のリクエストは停止し、失敗を報告します。自動的な課金リトライはしません。

`--batch-items`・`--batch-chars`でバッチ量、`--workers`で同時実行数を調整できます。`--limit-batches 1`は少量試験用で、全件収録完了の意味ではありません。完了判定には必ず`--check`を使います。

別のGo SDK版では既存ファイルへの追記を拒否します。別名の出力で生成・検証し、カタログと埋め込みデータの版・件数テストを一緒に更新してください。

## 外部依存ライブラリ：表示時に翻訳

バックエンドが実際の解決元を外部依存と判定し、定義コメントを取得できた場合だけ、`s`で表示した時点に`explain_agent`へ翻訳を依頼します。標準ライブラリやrepo独自関数には、この経路を使いません。

送信対象は関数名・シグネチャ・定義コメントです。プロジェクトのソース本文や履歴は送らず、プロジェクトルートの絶対パスもメタデータとして付けません。コメント中に含まれている文字列を秘密情報除去する機能ではありません。送信前提を確認した依存ライブラリで使用してください。

既存の行解説アダプターと同じJSON契約を使いますが、対象は合成バッファ`external-documentation.txt`です。言語は`text`、`content`は対象コメント、`version`はシグネチャとコメントを識別するハッシュです。応答は同じ`version`、日本語の`message`、空の`comments`配列が必要です。

同じウィンドウに訳文を反映し、成功した64件をNeovimセッション内でキャッシュします。閉じる・ソース変更・`:HodoCodeCancel`で処理を中止し、遅延応答でウィンドウを開き直しません。未設定・サイズ上限・タイムアウト・不正応答では、失敗理由と原文を残します。アダプターは一時ディレクトリから起動しますが、OSのサンドボックスではありません。
