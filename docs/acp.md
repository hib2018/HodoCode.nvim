# fxのACP接続

2026年11月時点。fx 0.0.18（6196071b3c1b）／ACP v1で実機検証しました。既定のJSON/JSONL接続は変更しません。

## 設定と操作

```lua
require('hodocode').setup({
  agent_transport = 'acp',
  agent = { 'fx', '--no-additional-dirs', 'acp', '--permission-mode', 'ask' },
  agent_timeout_ms = 120000,
  acp_cancel_timeout_ms = 3000,
  max_agent_bytes = 1024 * 1024,
})
```

- `e/i`で同じ会話を表示、画面内の`Enter/i`で質問、`A`／`:HodoCodeAgent`で編集を依頼します。表示は最新の末尾から始め、過去ログ閲覧中はスクロールを奪いません。
- 起動は最初の**送信**まで遅延します。初回だけ`initialize → session/new`、以降は同じ接続・セッションへ`session/prompt`を送ります。会話履歴全文をコピー・再送しません。
- 毎回、最新の未保存本文・対象ファイル・カーソル・依頼種別を送ります。embedded contextに対応しないエージェントではテキストへフォールバックします。
- 回答は逐次表示します。編集のJSONは「受信中・未確定」として表示し、途中のパッチを適用しません。ツール通知は短い状態表示、通常の通知は受信表示だけとし、思考・生ログ・任意のエラー本文を表示しません。
- `Esc/q/:q`で表示ウィンドウだけを閉じても、モード終了・別バッファ移動でも実行は継続します。
- `x`／`:HodoCodeCancel`で`session/cancel`を送り、中止応答待ちになります。元の`session/prompt`の終了まで次の依頼は受け付けません。猶予`acp_cancel_timeout_ms`を超えたら接続を停止します。中止後の回答は適用しません。
- 切断した依頼を自動再送しません。次の明示依頼時、対応する場合だけ同じIDの`session/resume`を試みます。復帰不可ならエラーにし、空の別会話へ黙って切り替えません。
- `VimLeavePre`で処理・権限画面・タイマー・接続を終了します。対応するエージェントへ`session/close`を要求し、プロセスを停止します。

モデル等を上書きするなら、fxの引数位置に注意してください。ワークスペース用フラグは`acp`より前、モデル・思考設定は後です。HodoCodeから利用者のグローバル設定を書き換えません。

```lua
agent = {
  'fx', '--no-additional-dirs', 'acp',
  '--provider', 'codex', '--model', 'gpt-6.2-sol', '--effort', 'auto',
  '--permission-mode', 'ask',
}
```

認証は事前に通常のfxで済ませてください。自動ログイン・認証方法の自動選択・権限モードの自動変更は行いません。確認できたサーバーのモードが`ask`以外なら送信を止めます。

## プロジェクトと履歴

明示した`root`を優先し、なければ対象ファイルから上へ`.git`・`go.mod`・`package.json`・`Cargo.toml`・`pyproject.toml`を探します。見つからなければ親ディレクトリです。パスは実パスへ正規化し、明示root外やシンボリックリンクによる範囲外への送信を拒否します。rootは存在する作業ディレクトリにしてください。

ACPではrootごとにHodoCodeの会話とネイティブ接続・セッションを分けます。A→B→AでAの会話へ戻れますが、実行中は別rootへ会話を切り替えません。同時依頼は引き続き全体で1件です。JSON接続の従来の単一会話は維持します。

**HodoCodeのメモリ内履歴と、fxが保存する履歴は別です。**

- 従来の同梱JSONアダプターは`fx ask --no-save`です。ACPの公開API／CLIでは同等の保存抑制方法を確認できていません。
- fxの公式仕様では通常の保存先は`~/.fx/sessions/`です。今回の実機確認でも`session/close`後に`fx session <今回作成したID> --json`で履歴を取得できました。クライアントは保存ファイルの内部形式・ディレクトリ名に依存しません。
- 保存対象には会話、ファイルパス、送信した未保存本文を含みます。マスク済み解説用の`a/E`とは異なり、生の文字列・コメントも送信・保存されます。機密情報を含むバッファで利用しないでください。
- Neovim終了や`session/close`は履歴削除ではありません。HodoCodeは今回のものを含め、fxの保存済み履歴を自動削除しません。
- Neovimを再起動した場合、HodoCodeは新しい表示用会話を開始します。過去のfx履歴の探索・自動インポート・別プロジェクトからのロードはしません。
- 長いネイティブ会話の圧縮・保存やセッションタイトル生成はfx側の設定・仕様に従います。HodoCodeが無断で古い発言を切り捨てたり再送したりするものではありません。

## 編集経路と権限

実fxで公開ダミーファイルを使って確認した結果：

| 検証 | 結果 |
| --- | --- |
| 未保存本文をembedded resourceとして質問 | ディスクと異なる送信本文を参照 |
| 同じセッションで追加の構造化編集依頼 | 前の合言葉を保持し、完全一致の部分パッチを返却。ディスク不変 |
| clientのファイル読取・書込機能を宣言して標準`edit_file`を許可 | clientの`fs/write_text_file`要求は来ず、fxがディスクへ直接書込 |

このため、今回の実装は**最終回答の構造化パッチ方式**です。fxへツール・直接書込を使わないよう指示し、`fs.readTextFile/writeTextFile`・端末機能を提供しません。未対応のclient側要求にはエラーを返します。新しいバッファ書込APIや独自の適用処理は増やしません。

- 権限画面はエージェントが提示したツール名・種類・対象パス・選択肢を表示します。`1`〜`9`、続きは`a`〜`g`、またはカーソル移動と`Enter`で選択します。閉じる・`q/Esc`は権限拒否、`x`は実行中の依頼自体を中止します。
- 許可できるのは`kind=read`かつ既知の`read_file`・`grep_files`・`glob_files`だけです。外部参照の必要性・対象を確認してください。
- 直接編集・シェル・MCP・不明な操作は、許可項目を選んでも許可しません。画面にも許可不可と表示します。アダプターが通常のワークスペース読取りを権限要求なしで行う可能性はあります。
- `ask`による権限制御とプロンプト指示であり、OSサンドボックスではありません。信頼するfx実行ファイル・プロジェクト設定だけを使ってください。`auto`／`full-access`は使いません。プロジェクトのMCP設定はfx側の仕様で引き継がれる場合があり、`mcpServers = []`はその無効化を保証しません。HodoCodeはMCP操作の権限を許可しません。

最終回答の`message`と`edits`（または互換`content`）を厳密に解析し、送信スナップショットの版を結び付けて、既存の`edit_patch.apply`と競合検証へ渡します。曖昧・重複・重なり・他フィールド・サイズ超過等を拒否します。フォーカス移動は競合ではありませんが、対象本文・名前・オプション・保存ファイルの変更は適用を止めます。

未保存反映、`u`、`:w`、`🤖`、明示`d`、依頼開始時の保存済み基準、LF/CRLF・末尾改行・BOMの扱いは[既存仕様](editing.md)と共通です。複数ファイルへの変更や標準編集ツールの自動許可は実装していません。

## 検証と計測

`make test`は偽ACPサーバーだけを使い、モデルを呼びません。分割JSON/UTF-8、双方向RPC、上限、不正応答、プロセス死亡、再利用・復帰、中止待ち・遅延結果、プロジェクト分離、部分パッチ・undo・競合・diff、表示・権限の取消を検証します。

実fxの試験は明示的なopt-inです。公開ダミーファイルのみで、最大14ターンを呼び出します。課金・使用量とfx側の保存が発生し得ます。

```sh
HODOCODE_ACP_LIVE=1 nvim --headless -u NONE -l tools/bench_acp.lua
```

[計測結果](acp-benchmark-2026-11.json)にはバージョン・モデル・思考設定と、同じ編集依頼の初回／継続を記録します。通常のスクリプトは各3組です。今回の測定は、先に通過した会話・手動編集フローを再実行せず、修正後の編集を各2組測定しました。

| エンドツーエンド中央値（各2組） | ACP | JSON |
| --- | --- | --- |
| 新規接続・初回 | 5.318秒 | 4.548秒 |
| 同じ会話の継続 | 3.240秒 | 5.389秒 |

条件はfx 0.0.18、codex／gpt-6.2-sol、effort `auto`です。今回は継続で短縮しましたが、初回はACPの方が遅く、少数標本から一般化しません。初回編集の実機試験で通知の混入を検出し、`session.notices`をboolではなく空オブジェクトとして宣言するよう修正しました。修正前の質問の最初のチャンク時刻は通知を含むため、応答速度の比較には使いません。履歴内の試験用最終JSONは正常で、JSON検証を緩めずに修正しています。

ACPの初期化完了・最初の本文・完了、検証から適用まで、エンドツーエンドを分けます。「初回」は新規接続でありOSキャッシュの冷却は行いません。JSON側は途中の本文を観測できないため初トークン時間は不明です。両方式で公開ソース・指示・モデルをそろえますが、内部のsystem prompt・会話表現・通信形式は同一ではありません。速度向上を保証しません。

公式資料：[fx ACP](https://fx.sh/docs/using-fx/acp)、[セッション保存](https://fx.sh/docs/using-fx/sessions)。
