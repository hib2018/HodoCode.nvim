# エージェントセッションと行直下diff

## 会話・依頼・画面の寿命

HodoCodeがNeovim本体の終了まで、会話履歴と実行中の依頼を管理します。表示ウィンドウは別管理です。

| 操作 | 会話・実行中の依頼 |
| --- | --- |
| `e/i`／`:HodoCodeChat` | 同じ履歴と現在の実行状況を表示・再表示 |
| 会話画面の`Enter`／`i` | 質問入力。変更は適用しない |
| ソース／会話画面の`A`、`:HodoCodeAgent [指示]` | 同じ会話への編集指示 |
| `Esc`／`q`／ウィンドウだけの`:q` | 画面を隠すだけ。依頼と履歴は継続 |
| 読解モード終了・別バッファへの移動 | 会話・依頼は継続 |
| `x`／`:HodoCodeCancel` | 実行中の依頼だけを中止。履歴は保持 |
| Neovim本体終了 | `VimLeavePre`でプロセス・タイマー・画面・一時リソースを終了 |

依頼入力は複数行で、`Ctrl-s`／`Ctrl-Enter`／ノーマルモードの`Enter`で送信します。挿入モードの`Enter`は改行、入力画面の`Esc`／ノーマルモードの`q`は未送信の下書きだけを取り消します。同時実行は1件です。実行中の再送信は理由を表示して止め、自動再送はしません。

例えば、`e`で質問 → `Esc`でソースへ戻って手動編集 → `A`で「今の変更を踏まえて残りも直して」→ `e`で同じ会話を再表示できます。質問の回答は送信時点のソースに基づきます。質問中に手動編集しても回答は会話へ保持しますが、編集依頼中に対象本文が変わった場合は変更を適用しません。

質問・編集は共通の`agent`設定を使います。旧`chat`の外部CLI端末・`{context}`引数は使用しません。`a/E`は独立したマスク済み解説経路のままです。**エージェント会話では、未保存の生バッファ全文とこのセッションの会話を送信します。**

## 送信・適用

実際の送信時点で、対象ファイル・本文・カーソル・改行等の設定・保存済み内容を捕捉します。入力を開いた後に手動編集しても、送信には最新の本文を使います。

- 依頼ごとに送信元バッファを保持します。フォーカス移動・元ウィンドウを閉じるだけでは失敗にしません。
- 編集では、送信元の本文・名前・設定・ディスク内容が変わっていないことを確認し、パッチ全体を検証してから一括適用します。
- 既存のUTF-8・LF/CRLF検証、版検証、完全一致・重複／重なり検出、サイズ制限を再利用します。
- 中止した依頼の遅延応答は破棄します。会話には中止・失敗・競合を記録し、未適用の変更を適用済み扱いにしません。
- 適用後も未保存です。`🤖`で変更行を示し、`u`で依頼前の本文（既存の未保存編集を含む）へ戻し、`:w`で保存できます。
- 完了しても会話画面を勝手に閉じたり、別バッファからフォーカスを奪ったりしません。非表示でも依頼は継続します。
- 重い再解析・ディスク再読込・自動保存・diffの自動表示はしません。

会話はNeovimのメモリ内だけに保持し、再起動をまたぐログ保存はしません。会話画面は`bufhidden=hide`で再利用し、表示用のundoを無効化します。隠した画面は定期的に描き直さず、再表示時に最新の履歴を描画します。ソースのundoには影響しません。

## `d`のインラインdiff

ソース上の`d`／`:HodoCodeDiff`でオン・オフします。別タブは開きません。

- 置換：変更後の実際の行を強調し、対応する旧行を`- `付きでその行の直下へ表示します。複数行でも行ごとに配置します。
- 新しい行に対応先のない旧行：変更範囲の最後の行の下へ並べます。
- 追加：追加した実際の行を強調します。
- 削除だけ：直前に残った行の下へ表示します。ファイル先頭での削除は先頭行の上です。
- 末尾改行・BOM・unix/dosだけの差異も仮想行で表示します。

旧行はnamespace `HodoCodeInlineDiff`のextmark `virt_lines`です。本文・行番号・変更フラグ・undo履歴は変えません。表示中の手動編集・API編集・undoを観測し、次の描画タイミングに差分を再計算します。オフ・改名・バッファ削除後に予約済み描画が復活しないようにします。

比較基準は対象バッファで**直近に実際に編集を適用した依頼の開始時保存済み内容**です。Git HEADや直前の未保存本文ではなく、既存の未保存編集も差分に含みます。回答のみ・失敗・変更なしでは更新せず、保存しても保持します。基準がなければdiffをオンにした時点のディスク内容を固定します。その後の手動編集ではディスクを読み直しません。新規ファイルの基準は空です。

## アダプター入力

標準入力は1件のJSONです。既存の`prompt`／`buffer`に会話を追加します。

```json
{"session_id":"Neovim内で共通のID","request_id":"依頼ごとのID","intent":"edit","history":[{"role":"user","content":"前の質問","intent":"chat","file":"main.go","request_id":"前の依頼ID","status":"sent"},{"role":"assistant","content":"前の回答","status":"nochange"}],"prompt":"今の変更を踏まえて残りも直して","buffer":{"path":"/project/main.go","content":"最新の未保存本文\n","modified":true,"filetype":"go","cursor":[1,0]}}
```

- `intent`は`chat`または`edit`。質問は回答のみ、編集指示だけが変更対象です。
- `history`は現在の依頼より前の会話です。今回の`prompt`を二重に追加しません。
- 会話の`role`は`user`／`assistant`、`content`は文字列です。ファイル名・種別・依頼ID・結果のメタデータを伴います。
- `status`／`outcome`は適用・変更なし・中止・競合等を区別します。適用済みの部分パッチを`edits`に含む場合もあります。古いバッファ全文のコピーを毎回積み増す方式ではなく、最新の`buffer.content`を正本とします。
- `cursor`は1始まりの行番号と0始まりのバイト列位置です。送信前の再確認はしません。
- このセッションで送信した会話以外のファイル・外部履歴は探索しません。以前に別ファイルで交わした会話も同じ履歴へ残るため、送信先と内容に注意してください。

既存のPATH等は継承し、`HODOCODE_EDIT_PROTOCOL=2`と`HODOCODE_AGENT_TIMEOUT_MS`を設定します。同梱fxアダプターは会話をモデルへ渡し、ファイルの絶対パスをメタデータではbasenameへ変換します。入力内のユーザー発言そのものに書かれたパス等を匿名化する保証はありません。

旧アダプターの単一JSON応答も受け付けますが、**会話共有には新しい入力の`history`へ対応する必要があります**。同梱fxアダプターは古いクライアント（protocol変数なし）へは従来形式の応答を維持します。

## アダプター出力とパッチ検証

標準出力は1行1JSONです。任意個の`status`の後、`result`または`error`を1件返して終了します。終端後の追加イベント、不正な行、終端の欠落、サイズ超過は全体を拒否します。最後の改行は省略可能です。

```jsonl
{"event":"status","phase":"waiting","elapsed_ms":1000}
{"event":"result","version":"送信したbuffer.contentのUTF-8バイト列のSHA-256（64桁）","message":"変更の説明","edits":[{"old_text":"value = 1","new_text":"value = 2"}]}
```

`status.phase`は`starting`・`waiting`・`received`・`validating`。経過時間はクライアントでも計測します。fxヘルパーの通知は処理段階・生存確認で、モデルの思考やトークンのストリーミングではありません。

`result`には文字列の`message`と送信本文のSHA-256である`version`が必要です。`edits: []`／編集フィールドなしは変更なし、`content: "全文"`は全文置換の互換経路です。`edits`と`content`の併記は拒否します。`chat`では`content`や変更を含む`edits`を拒否します。

- 部分編集は最大256件、文字列の`old_text`／`new_text`だけを指定します。他ファイル・コマンド・正規表現は扱いません。
- 全ての置換元は**同じ送信スナップショット**を参照し、先の編集の結果には一致させません。
- 各`old_text`が元の全文にちょうど1回だけ現れ、範囲が重ならない必要があります。曖昧な一致・近似置換・自動的な全件置換はしません。
- 空の`old_text`は元本文が空の場合の単独挿入だけ許可します。`new_text: ""`は削除です。
- 適用後のサイズ・UTF-8・改行も検証し、不正な1件だけを飛ばして適用することはありません。

旧形式`{"message":"説明","content":"全文"}`は整形済みJSONでも読み取れ、版の省略も許可します。旧形式でも編集時の競合検証は省略しません。

## 失敗・上限・実行環境

```jsonl
{"event":"error","code":"timeout","elapsed_ms":117500}
```

時間切れ、起動失敗、接続先の異常終了、不正JSON・応答、サイズ超過、中止を分類し、日本語の理由と経過時間を履歴へ記録します。標準エラーやエラーイベントの任意メッセージは画面へ転送しません。`provider_exit`だけでは認証・通信などの根本原因を確定できません。

入力（会話込み）と標準出力・標準エラー合計はそれぞれ`max_agent_bytes`以内、fxヘルパー内部の要求・応答は各1MiBまでです。上限超過時は自動的な履歴削除・要約・再送をせず送信を止めます。会話表示は保持します。

fxの待機時間は`agent_timeout_ms`（既定120秒）から終了処理の余裕（最大2.5秒、短い制限では20%）を差し引きます。固定115秒の内側制限はありません。部分編集は返却トークンを減らしますが、入力全文を省略するものでも、必ず高速になる保証でもありません。

専用cwdは権限0700です。fxの応答は文字を加工する`final_output`ではなく生の`output`を読みます。ツール・他ファイル読取り・直接書込みを禁止する指示を渡しますが、OSのサンドボックスではありません。信頼できるアダプターだけを指定してください。
