# バッファ編集ブリッジ

## 操作と維持する機能

- `:HodoCode`で分類・キー付きの全操作を選択できます。既存コマンド・HodoCodeモードのキーも使えます。
- `A`で複数行の指示ポップアップ。`Ctrl-s`／`Ctrl-Enter`／ノーマルモードの`Enter`で送信。挿入モードの`Enter`は改行、`Esc`／ノーマルモードの`q`は取消です。
- 待機中は実際の段階と経過時間を表示します。生成率やモデルの思考を推測した表示ではありません。`x`／`:HodoCodeCancel`／実行フロートを閉じる操作で中止します。
- 結果を全件検証後に未保存バッファへ一括適用し、ソースへ戻って再描画・`🤖`表示します。重い再解析・ディスク再読込・自動保存・自動diffはしません。
- `d`だけがdiffを開きます。基準は要求開始時の保存済みディスク内容で、既存の未保存編集も差分に含まれます。失敗・変更なし・回答のみでは基準を更新しません。`u`で要求前の未保存編集を含む本文へ戻せます。
- `a`はカーソル行、`E`は現在の関数だけのマスク済み解説です。編集用の生バッファ送信とは別経路です。チャット・図・ツリー・構文／変数情報・DAP・関数マーカー・読解履歴も従来どおりです。
- 内容表示フロートの`q`／`Esc`はソースへ戻り、ソースの`q`／`Esc`はモードを終了します。ターミナルは先に`Ctrl-\ Ctrl-n`でノーマルモードへ戻ってください。

## 入力・実行環境

標準入力は従来と同じJSONを1件送ります。

```json
{"prompt":"変更指示","buffer":{"path":"/project/main.go","content":"元の全文\n","modified":true,"filetype":"go","cursor":[1,0]}}
```

`content`は未保存内容・文字列・コメントを含む全文です。行末はNeovimから組み立てた本文で、末尾改行を含む場合もあります。`cursor`は1始まりの行番号と0始まりのバイト列位置です。送信前の再確認はなく、他ファイルや会話履歴は添付しません。

新しいクライアントは次の環境変数を追加します。既存のPATH等は継承します。

| 変数 | 意味 |
| --- | --- |
| `HODOCODE_EDIT_PROTOCOL=2` | JSON Linesの進捗・版付き部分編集を扱えるクライアント |
| `HODOCODE_AGENT_TIMEOUT_MS` | `setup`の`agent_timeout_ms`。外側の処理時間制限と同じ値 |

同梱`examples/edit-fx.py`はprotocol 2の場合に部分編集を依頼し、未指定では従来の全文JSONを返します。古い導入先が新しいスクリプトを参照していても、いきなり応答形式が変わりません。新しいクライアントも旧アダプターの全文JSONを引き続き扱います。

fx用ヘルパーは`agent_timeout_ms`から終了処理の余裕（最大2.5秒、短い制限では20%）を差し引いて待ちます。固定115秒の内側制限はありません。起動後に別のfx要求を自動再送することもありません。

## 出力

標準出力は1行1JSONです。任意個の`status`の後、`result`または`error`を1件返し、終了してください。終端後の追加イベント・不正な行・終端の欠落・サイズ超過は全体を拒否します。最後の改行は省略可能です。

```jsonl
{"event":"status","phase":"waiting","elapsed_ms":1000}
{"event":"result","version":"元のbuffer.contentのUTF-8バイト列のSHA-256（64桁）","message":"変更の説明","edits":[{"old_text":"value = 1","new_text":"value = 2"}]}
```

`status.phase`は`starting`・`waiting`・`received`・`validating`。`elapsed_ms`は省略可能な非負の数です。表示の経過時間はクライアント自身でも計測します。同梱fxヘルパーの待機通知は生存確認であり、fxからモデルのトークンをストリーミングしているわけではありません。

`result`は文字列の`message`、要求全文のSHA-256である`version`を持ちます。次のどれかを指定できます。

| 形式 | 扱い |
| --- | --- |
| `edits: [...]` | 全編集が一致した場合だけ一括適用 |
| `edits: []`／編集フィールドなし | 変更せず回答を表示 |
| `content: "全文"` | 全文置換の互換経路 |

`edits`と`content`の併記は拒否します。旧形式の単一JSON `{"message":"説明","content":"全文"}` は改行付き・整形済みでも読み取れ、版フィールド省略も許可します。旧形式でも操作元の版・ディスク・設定の競合検証は省略しません。

### 部分編集の規則

- 最大256件。各編集は文字列の`old_text`と`new_text`だけを指定します。パス・コマンド・正規表現・他ファイルの編集は扱いません。
- **全ての置換元は同じ元スナップショットを参照**します。先の編集の結果を、次の編集の置換元にはしません。順序に依存せず適用します。
- `old_text`は元の全文にちょうど1回だけ現れ、他の編集と重ならない必要があります。複数一致する場合は前後の文脈を含めてください。曖昧な一致・近似置換・自動的な全件置換はしません。
- 空の`old_text`は元の本文が空の場合の単独挿入だけ許可します。既存本文への追加は周辺の本文を置換元に含めます。`new_text: ""`は削除です。
- 適用後のサイズ・UTF-8・改行も検証します。不正な1件だけを飛ばすことはなく、全件を適用せず終了します。
- バッファの本文・名前・元ウィンドウ・改行設定・保存済みディスクが変わっていた場合も全件拒否します。途中の進捗を受け取っただけで変更を適用しません。

## 失敗・制限・送信保護

```jsonl
{"event":"error","code":"timeout","elapsed_ms":117500}
```

同梱ヘルパーは時間切れを`timeout`、起動失敗を`spawn_failed`、接続先の異常終了を`provider_exit`、JSON不正を`invalid_json`、応答形式不正を`invalid_response`、出力超過を`size_limit`、中止を`cancelled`として返します。カスタムアダプターは`authentication`・`rate_limit`・`transport`も区別できます。エラーの`message`や標準エラーの生データは表示せず、分類ごとの日本語と経過時間を表示します。`provider_exit`だけでは認証・通信などの根本原因を確定できません。

入力と標準出力・標準エラーの合計はそれぞれ`max_agent_bytes`まで、fxヘルパー内部の要求・応答は各1MiBまでです。新しいプロトコルでも上限を無くしません。部分編集は返却トークンの削減が目的であり、入力全文の送信を省略するものでも、必ず高速になる保証でもありません。

一時ディレクトリは権限0700、fxへのファイル情報はbasenameのみです。fxの構造化応答では、文字を加工する`final_output`ではなく生の`output`を読みます。ツール・他ファイルの読取り・直接書込みを禁止する指示を渡しますが、OSのサンドボックスではありません。信頼できるアダプターだけを指定してください。
